# React guidance comparison and implemented coverage

Reviewed 12 November 2026 against the seven sources identified for the lens. The Effect and state-structure pages form one source group. These are maintained documents; the review date is not a claim that each page was published that day.

The lens analyzes other projects. This comparison concerns its analyzers and evidence contracts, rather than changing this CLI into a React application.

## Evidence and policy

The three new static candidates (`derived-state-effect`, `eager-state-initializer`, and `next-root-client-boundary`) are review-only, unresolved, low-confidence heuristics. They never automatically edit source or establish a performance regression. Their IDs preserve unrelated line movement; changing the source anchor can change identity. Their scope is bounded syntax, not a complete implementation of the source documents. They can overlap upstream lint findings and are not independent confirmation of those findings.

The `rule_coverage` inventory includes the official reference's rules and additional rules enabled by the installed plugin. The plugin version and selected preset are recorded. Unknown future rules retain the existing review policy. Existing correctness/blocking contracts remain in force; no new blocker was added.

The React guidance and runtime interpretation versions participate in analysis identity so saved artifacts from older interpretations become stale. Existing audit, MCP and LSP paths consume React-health records; the new runtime format uses the existing `runtime_inputs.react_profiler` input and freshness checks.
